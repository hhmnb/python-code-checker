Python 脚本开发专业指令库（Skills）—— 最终完整版（含 AI 输出验证与强制服从）
========================================
使用方法：在发送给 AI 的消息末尾，按需选取以下指令编号，以 "请遵循以下专业标准: #编号1, #编号2, ..." 的格式附加即可。

一、设计阶段
1. 请先分析需求，输出模块化设计方案，再给出函数清单。
2. 将复杂逻辑拆分为高内聚、低耦合的函数包，每个函数职责单一且命名清晰。
3. 设计数据预处理、指标计算和结果存储的函数流程，基于给定的数据样本。
4. 设定首次运行时间为基准，后续按时间增量处理数据，确保断点续跑能力。
5. 提供脚本的 CLI 入口（argparse），支持命令行参数控制关键行为，并输出清晰的 help 信息。
6. 为所有 CLI 脚本添加 --dry-run 参数，允许用户预览即将执行的操作而不实际执行，提供安全保障。
7. 设计配置管理方案，将可变参数（如 API 密钥、超时时间、文件路径）抽取到独立的配置文件（.env 或 config.yaml）中，并通过环境变量区分开发/生产环境。

二、编码规范
8. 所有代码必须包含完整的类型注解和中文文档字符串（docstring）。
9. 所有 Python 代码必须符合 PEP 8 规范，使用 4 空格缩进，行宽不超过 120 字符，导入语句按标准库、第三方库、本地模块分组。
10. 为每个 .py 文件添加文件头注释，包含文件名、功能简述、作者、创建日期和修改记录。
11. 如果函数内部有复杂逻辑，请添加行内注释解释关键步骤，但避免过度注释显而易见的代码。
12. 为所有公开函数和类编写详细的 docstring，包含参数说明、返回值、可能抛出的异常以及使用示例。
13. 如果函数修改了可变参数（如列表、字典），必须在 docstring 中明确说明该副作用。
14. 对于涉及正则表达式的代码，请在注释中说明正则模式的用途，并附带一个匹配示例。

三、代码输出与防偷懒
15. 输出完善后的完整代码，不精简、不省略，保持可运行状态。禁止使用占位符、pass 语句或“此处省略”等含糊表述。
16. 输出结果除了终端打印外，支持导出为 CSV、JSON 或 Excel 文件，并在文件名中包含时间戳以便归档。
17. 在提供完整代码后，附带一份简单的 README 概要，包含功能说明、依赖安装、配置方法和启动命令。
18. 提供 .gitignore 文件内容，确保不会将敏感信息、缓存文件、虚拟环境提交到版本控制。
56. 所有函数必须给出完整的实现，不允许只写函数签名而不写函数体，不允许只写伪代码或思路说明。
57. 在输出代码之前，请用一句话明确描述最终交付物的完整形态（例如：“您将获得一个包含 3 个模块的完整可运行项目”），以便我确认效果。
58. 如果需求涉及多个文件，必须列出完整的文件目录结构，并逐一提供每个文件的内容。
59. 不允许使用“同上”、“类似”、“其他函数同理”等省略性表述，每个函数必须独立完整写出。
60. 对于需要外部依赖的代码，必须给出精确的 pip install 命令，并确认已在代码中正确导入。

四、异常处理与健壮性
19. 思考当前实现可能存在的边界条件、异常情况和逻辑缺陷，并给出改进建议。
20. 检查是否存在资源泄露、线程安全、网络异常未处理等运行时隐患。
21. 所有异常捕获必须指定具体异常类型（如 ValueError, ConnectionError），禁止使用裸 except: 或 except Exception: 捕获所有异常。
22. 对外部调用（网络请求、数据库操作）添加重试机制和超时控制，并记录错误日志。
23. 为所有外部接口（API 调用、数据库连接、文件读写）添加异常捕获，并返回自定义的错误码或降级策略。
24. 分析脚本的运行流程，输出包含步骤编号、输入输出和异常处理的完整工作流说明。
25. 用表格列出所有可能失败的点、失败原因及对应的自动恢复策略。

五、测试与质量
26. 为关键函数生成对应的单元测试用例（pytest 格式），覆盖正常、异常和边界场景。
27. 通过 mypy、bandit 等静态分析工具检查代码安全性，禁止使用 eval、exec、pickle.loads 不可信数据等不安全调用。
28. 所有用户输入必须进行前端验证（输入格式、长度限制、字符过滤）和后端验证，防止注入攻击和非法数据写入。

六、日志与输出
29. 在关键节点添加结构化日志（使用 logging 模块），记录时间戳、操作名称、输入参数和输出结果，便于问题追踪。
30. 输出结果时，使用 logging 模块而非 print，并支持 --verbose / --quiet 参数控制日志级别。
31. 提供简洁但功能完整的报告输出，包含关键指标的量化数据和趋势描述。

七、性能与资源管理
32. 对于需要处理大量数据的场景，优先使用生成器或迭代器而非直接返回完整列表，以减少内存占用。
33. 使用上下文管理器管理资源（文件、数据库连接、网络会话），确保即使发生异常也能正确释放，避免内存泄漏。
34. 对于长时间运行或批量处理任务，实现分页或流式处理，监控内存使用峰值，必要时调用 gc.collect() 或限制缓存大小。
35. 如果代码需要并行处理，请使用 concurrent.futures 或 multiprocessing，并提供进程/线程池大小的配置选项。
36. 对于涉及异步操作（如网络请求、文件 IO）的函数，优先使用 async/await 语法，并说明为什么选择异步而非同步。

八、数据与状态管理
37. 设计数据持久化方案时，考虑使用 SQLite 作为本地轻量数据库，并提供建表语句、索引设计和迁移脚本。
38. 对于需要增量处理的场景，维护一个状态文件（如 JSON 或 SQLite），记录上一次处理的位置或时间戳，确保程序中断后可从断点继续。
39. 为每个数据模型或核心概念定义 dataclass 或 Pydantic 模型，统一数据结构。
40. 对涉及金额、浮点数的计算使用 Decimal 或高精度整数，并添加舍入策略说明，避免精度丢失。
41. 在处理用户输入或外部数据时，始终进行类型校验和范围检查，使用 assert 或显式校验逻辑。

九、安全与敏感信息
42. 对敏感信息（密钥、密码）禁止硬编码，必须通过环境变量或加密配置文件获取，并在日志中自动脱敏。
43. 为所有网络请求添加 User-Agent 和必要的请求头模拟，并处理常见的 HTTP 错误状态码（如 429、503）并实现退避重试。
44. 编写代码时优先使用标准库或轻量级依赖，如需引入第三方库，请注明版本并在输出中附带安装命令。
45. 如果代码依赖操作系统特定功能（如 os.system、信号处理），请提供跨平台兼容的方案或降级策略。

十、GUI 界面
46. GUI 框架选型优先使用 PySide6/PyQt6 或 Tkinter，并提供界面布局的详细说明（布局管理器、控件层级、尺寸策略）。
47. 所有 GUI 操作必须在主线程中执行，耗时任务使用 QThread/threading.Thread 或异步机制，防止界面冻结，并提供取消操作的入口。
48. 为 GUI 窗体设置合理的最小尺寸和默认尺寸，支持窗口缩放时控件自适应（大小策略、伸缩因子、网格布局）。
49. 所有用户交互控件（按钮、输入框、复选框）必须提供清晰的标签和状态反馈，操作后通过状态栏或提示框告知用户当前状态。
50. 界面布局遵循操作直觉：高频操作用快捷键或工具栏，重要功能置于显眼位置，危险操作（删除、重置）必须有二次确认。

十一、并发与多线程
51. 多线程/多进程共享数据时，使用 threading.Lock、queue.Queue 或 concurrent.futures 安全通信，避免竞态条件和死锁，并添加超时机制。
52. 对于长时间运行的任务，提供进度回调或生成器函数，以便外部调用者获取实时进度。

十二、扩展与可维护性
53. 确保代码可扩展、可复用，遵循单一职责和开闭原则。
